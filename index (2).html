Módulo 01

Fundamentos de virtualización y nube

Conceptos esenciales para entender cómo se organizan los recursos informáticos actuales.

¿Qué es la virtualización?

Es una tecnología que permite crear representaciones virtuales de recursos físicos, como servidores, sistemas operativos, almacenamiento y redes. Un servidor físico puede alojar varias máquinas virtuales aisladas entre sí.

¿Qué es la computación en la nube?

Es un modelo que permite acceder por red a recursos informáticos configurables, como procesamiento, almacenamiento y servicios, que pueden aprovisionarse según la demanda.

Máquina virtual (VM)

Entorno de software que emula un equipo físico. Tiene recursos asignados, sistema operativo y aplicaciones, y funciona sobre un hipervisor.

Hipervisor

Capa de software que crea y administra máquinas virtuales, distribuyendo recursos físicos como CPU, memoria, almacenamiento y red.

Modelos de servicio en la nube

Los modelos describen qué parte de la infraestructura administra el proveedor y qué parte administra el cliente.

ModeloDescripciónResponsabilidad del usuario
IaaSInfraestructura como servicio: cómputo, redes y almacenamiento virtual.Sistema operativo, aplicaciones, datos y configuraciones.
PaaSPlataforma como servicio para desarrollar y ejecutar aplicaciones.Código, datos y configuración de la aplicación.
SaaSSoftware listo para utilizarse a través de Internet.Uso, usuarios, datos y opciones disponibles del servicio.

Tipos de nube

Nube pública

Los recursos son ofrecidos por un proveedor a través de su plataforma, como Microsoft Azure.

Nube privada

Infraestructura dedicada a una organización, con mayor control sobre su entorno y administración.

Nube híbrida

Integra infraestructura privada o local con servicios de nube pública, permitiendo distribuir cargas de trabajo.

Ejemplo: una organización puede mantener algunos sistemas en servidores propios y utilizar Azure para alojar recursos adicionales o respaldar servicios.
Módulo 02

Virtualización con VMware

VMware permite consolidar servidores y administrar máquinas virtuales sobre infraestructura física.

▣

VMware ESXi

Hipervisor de tipo 1 que se instala directamente en el servidor físico. Administra la ejecución de máquinas virtuales y el acceso a recursos de hardware.

  • Asignación de CPU y memoria.
  • Almacenamiento de discos virtuales.
  • Adaptadores y redes virtuales.
  • Consola de administración del host.
🗂️

vCenter Server

Plataforma de administración centralizada para entornos VMware vSphere. Facilita gestionar hosts ESXi, inventario, redes, almacenamiento y máquinas virtuales.

  • Administración central de hosts.
  • Gestión de inventario y permisos.
  • Supervisión de recursos.
  • Operaciones coordinadas del entorno.

Componentes de una máquina virtual

CPU virtual

Procesamiento asignado a la máquina virtual mediante uno o más vCPU.

Memoria RAM

Memoria que utiliza el sistema operativo invitado y sus aplicaciones.

Disco virtual

Almacenamiento virtual donde se guardan sistema operativo, archivos y aplicaciones.

Adaptador de red

Conecta la VM a redes virtuales y permite su comunicación con otros equipos.

Sistema operativo

Software invitado instalado dentro de la máquina virtual.

Snapshot

Captura del estado de una VM en un momento determinado; no sustituye una copia de seguridad.

Módulo 03

Contenedores y Docker

Los contenedores facilitan empaquetar y ejecutar aplicaciones de forma consistente en distintos entornos compatibles.

¿Qué es Docker?

Plataforma para construir, distribuir y ejecutar aplicaciones en contenedores. Utiliza imágenes como plantillas de solo lectura y crea contenedores a partir de ellas.

Contenedor vs. máquina virtual

Una VM incluye un sistema operativo invitado sobre un hipervisor. Un contenedor aísla procesos y comparte el kernel del sistema anfitrión, por lo que suele ser más ligero.

Conceptos principales

Imagen

Plantilla que contiene la aplicación y sus dependencias para crear contenedores.

Contenedor

Instancia en ejecución de una imagen, con procesos y configuración propios.

Volumen

Mecanismo para conservar datos fuera del ciclo de vida del contenedor.

Red Docker

Permite la comunicación entre contenedores y con otros destinos de red.

Dockerfile

Archivo de instrucciones utilizado para construir una imagen personalizada.

Docker Compose

Herramienta para definir y administrar aplicaciones compuestas por varios servicios.

Comandos básicos de referencia

Ejemplos generales para consultar Docker. Ejecútalos en un equipo donde Docker esté instalado.

docker --version
docker ps -a
docker images
docker run -d -p 8080:80 --name web nginx
docker logs web
docker stop web
docker start web
Ejemplo: al ejecutar un contenedor Nginx con el puerto 8080 del host enlazado al puerto 80 del contenedor, se puede probar el servicio desde el navegador mediante la dirección IP del host y el puerto 8080.

🔐

Módulo 05

Redes y conectividad

Las redes virtuales conectan máquinas, contenedores y servicios locales o en la nube.

Direccionamiento IP

Las direcciones IPv4 e IPv6 identifican interfaces y permiten enrutar tráfico entre redes. La planificación debe evitar solapamientos de subredes.

Segmentación

Las VLAN separan dominios de broadcast y ayudan a organizar usuarios, servidores, administración y otros servicios.

Firewall y reglas

Controlan qué conexiones pueden entrar o salir, aplicando el principio de permitir solo el tráfico necesario.

VPN y túneles

WireGuard, por ejemplo, permite establecer túneles VPN para conectar redes o equipos mediante comunicación cifrada.

Diseño recomendado: documenta subredes, gateways, DNS, puertos, reglas de firewall y rutas. Antes de habilitar un servicio, verifica desde qué redes debe ser accesible.
Módulo 06

Seguridad y administración

La seguridad debe incorporarse desde el diseño y mantenerse durante toda la operación de la infraestructura.

Identidad y acceso

Utilizar cuentas individuales, autenticación robusta, permisos mínimos y revisión periódica de privilegios.

Actualizaciones

Aplicar parches de seguridad a hipervisores, sistemas operativos, contenedores y aplicaciones.

Protección de red

Segmentar redes, restringir puertos, filtrar tráfico y evitar exponer servicios de administración a Internet.

Copias de seguridad

Definir frecuencia, retención y ubicación de respaldos. Probar restauraciones periódicamente.

Monitoreo

Observar uso de CPU, RAM, almacenamiento, disponibilidad, eventos y registros de seguridad.

Continuidad

Documentar dependencias, procedimientos de recuperación y responsables de operación.

Laboratorios y recursos prácticos

Espacio para documentar ejercicios, procedimientos y evidencias desarrolladas durante la electiva.

Personaliza esta sección: agrega capturas de pantalla de tus prácticas, las direcciones IP utilizadas en tu laboratorio y los resultados de las verificaciones. No publiques contraseñas, tokens ni claves privadas.

Práctica: administración de máquinas virtuales

  1. Identificar el host ESXi y sus recursos físicos.
  2. Crear o revisar una máquina virtual.
  3. Asignar CPU, memoria, disco y adaptador de red.
  4. Instalar o iniciar el sistema operativo invitado.
  5. Verificar conectividad y consumo de recursos.

Evidencia sugerida: captura del inventario de vCenter, configuración de hardware de la VM y prueba de conectividad.

Práctica: despliegue de un sitio web con Docker

  1. Comprobar que Docker esté instalado.
  2. Descargar una imagen, por ejemplo Nginx.
  3. Crear y ejecutar el contenedor.
  4. Publicar un puerto del contenedor en el host.
  5. Comprobar el sitio desde el navegador y revisar los registros.

Evidencia sugerida: salida de docker ps y captura del sitio web cargado.

Práctica: recursos básicos en Azure

  1. Seleccionar la suscripción y región permitida.
  2. Crear un grupo de recursos.
  3. Configurar una red virtual y subred.
  4. Desplegar una máquina virtual con acceso controlado.
  5. Verificar conectividad y revisar costos y recursos asociados.

Evidencia sugerida: capturas de la VM, red virtual y estado de los recursos.

Práctica: conectividad y servicios de red

  1. Documentar el direccionamiento IP y las subredes.
  2. Verificar gateway y resolución DNS.
  3. Comprobar reglas de firewall y puertos necesarios.
  4. Probar conectividad entre redes o mediante VPN cuando corresponda.
  5. Registrar resultados y corregir fallos.

Evidencia sugerida: diagrama de red, resultados de ping, traceroute y pruebas de servicio.
